PDF Desktop App — Tauri v2 + pdf.js

Context

Build a minimal desktop PDF viewer for Linux using pdf.js for rendering. The app should produce the smallest possible distributable — hence Tauri v2 (system WebKitGTK webview, ~5-15MB AppImage vs Electron's ~150MB+). Primary distribution: AppImage.

Tech Stack

  • Tauri v2 — Rust backend, system webview frontend
  • pdf.js — Mozilla's PDF rendering library
  • Vanilla HTML/CSS/JS — no frontend framework (smallest bundle)
  • npm (via volta) — package management
  • @tauri-apps/cli — Tauri CLI as npm devDependency

Project Structure

├── src-tauri/

Implementation Steps

1. Initialize project scaffolding

  • Create package.json with scripts and dependencies:
  • devDeps: @tauri-apps/cli
  • deps: pdfjs-dist
  • Run npm install

2. Set up Tauri backend (src-tauri/)

  • Cargo.toml — tauri v2 dependencies
  • tauri.conf.json — app config, window settings, file associations, AppImage bundle config
  • capabilities/default.json — permissions (dialog:open, fs:read, etc.)
  • src/lib.rs — minimal Tauri app entry point
  • src/main.rs — binary entry point

3. Build the frontend (src/)

  • index.html — toolbar (open, prev/next page, zoom, page counter) + canvas container
  • style.css — dark theme, responsive layout, toolbar styling
  • main.js — core logic:
  • Initialize pdf.js with worker
  • Open PDFs via Tauri file dialog
  • Read file bytes via Tauri fs plugin
  • Render pages to canvas
  • Page navigation (prev/next/go-to)
  • Zoom controls
  • Keyboard shortcuts (arrows, +/-, Ctrl+O)
  • Handle file passed as CLI argument (for "Open with" from file manager)

4. Configure AppImage bundling

  • Set bundle.targets to ["appimage"] in tauri.conf.json
  • Configure file associations for .pdf MIME type
  • Set appropriate app identifier and metadata

5. Add .gitignore

  • node_modules, target, dist

Key Design Decisions

  • No frontend framework — pdf.js + vanilla JS is sufficient, keeps bundle tiny
  • Tauri fs + dialog plugins — for native file open dialog and reading PDF bytes
  • pdf.js worker from node_modules — copy or reference from pdfjs-dist package
  • CLI arg handling — so PDFs can be opened via "Open with" in file managers

Verification

  1. npm run tauri dev — launches app, can open and view PDFs
  2. npm run tauri build — produces AppImage in src-tauri/target/release/bundle/appimage/
  3. Test: open PDF via toolbar button, navigate pages, zoom in/out, keyboard shortcuts

## Tauri v2 Drag and Drop File Event API

### 1. Event Names

In Tauri v2, the old v1 event `"tauri://file-drop"` has been replaced with **four separate events**:

| Constant | String Value |
|---|---|
| `TauriEvent.DRAG_ENTER` | `"tauri://drag-enter"` |
| `TauriEvent.DRAG_OVER` | `"tauri://drag-over"` |
| `TauriEvent.DRAG_DROP` | `"tauri://drag-drop"` |
| `TauriEvent.DRAG_LEAVE` | `"tauri://drag-leave"` |

However, you should **not** listen to these raw events directly. Instead, use the `onDragDropEvent()` convenience method which wraps all four into a single handler.

### 2. Payload Structure (TypeScript Type)

The `DragDropEvent` is a discriminated union type with four variants:

```typescript
type DragDropEvent =
  | { type: 'enter'; paths: string[]; position: PhysicalPosition }
  | { type: 'over'; position: PhysicalPosition }
  | { type: 'drop'; paths: string[]; position: PhysicalPosition }
  | { type: 'leave' }
```

- **`enter`** -- User starts hovering files over the webview. Includes the list of file `paths` and cursor `position`.
- **`over`** -- User continues hovering (mouse moves). Only includes cursor `position`.
- **`drop`** -- User releases files. Includes the list of file `paths` and the drop `position`.
- **`leave`** -- User cancels or drags files away from the window. No payload data.

### 3. Configuration / Permissions

**No special capability or permission is needed.** Drag-and-drop is built into the webview and is **enabled by default**.

The relevant config key is `dragDropEnabled` (renamed from v1's `fileDropEnabled`), located in `tauri.conf.json`:

```json
{
  "app": {
    "windows": [
      {
        "dragDropEnabled": true
      }
    ]
  }
}
```

**Important caveat:** When Tauri's internal drag-drop system is enabled (`dragDropEnabled: true`, the default), **native HTML5 drag-and-drop DOM events are disabled**. The two systems are mutually exclusive. If you want to use the browser's native `ondrop`/`ondragover` events instead, set `dragDropEnabled: false` -- but then you lose access to file system paths (you only get file contents via the browser File API).

### 4. No Plugin Needed

Drag-and-drop is **built into the core Tauri webview/window API**. There is no plugin required. You import from `@tauri-apps/api/webview` or `@tauri-apps/api/window`.

### 5. Exact Code to Listen for File Drop Events

```typescript
import { getCurrentWebview } from "@tauri-apps/api/webview";

// Set up the drag-drop listener
const unlisten = await getCurrentWebview().onDragDropEvent((event) => {
  if (event.payload.type === 'enter') {
    console.log('Drag entered with files:', event.payload.paths);
    console.log('Position:', event.payload.position);
  } else if (event.payload.type === 'over') {
    console.log('Dragging over at position:', event.payload.position);
  } else if (event.payload.type === 'drop') {
    console.log('Files dropped:', event.payload.paths);
    console.log('Drop position:', event.payload.position);
    // event.payload.paths is string[] of absolute file system paths
    // e.g. ["/home/user/documents/file.pdf"]
  } else if (event.payload.type === 'leave') {
    console.log('Drag cancelled / left window');
  }
});

// IMPORTANT: Call unlisten() when your component unmounts / you no longer need it
// unlisten();
```

You can also use `getCurrentWindow().onDragDropEvent(...)` from `@tauri-apps/api/window` -- both approaches work. The `getCurrentWebview()` variant is the more precise one if you have multiple webviews.

**Note:** When the browser DevTools debugger panel is open, the `position` value may be inaccurate due to a known limitation.
